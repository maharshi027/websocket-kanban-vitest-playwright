# Contributing Guide

## Assessment Submission Guidelines

### What to Submit

1. **Complete Codebase**
   - All source files
   - Configuration files
   - Test files
   - Documentation

2. **README Updates**
   - Document any new features
   - Update setup instructions if needed
   - Add usage examples

3. **Test Coverage**
   - Ensure all tests pass
   - Add tests for new features
   - Maintain or improve coverage

### Code Quality Standards

#### JavaScript/React
- Use functional components with hooks
- Follow React best practices
- Use meaningful variable names
- Add comments for complex logic
- Keep components focused and reusable

#### CSS
- Use BEM naming convention when appropriate
- Keep styles modular
- Ensure responsive design
- Use CSS variables for theming

#### Testing
- Write descriptive test names
- Test both success and error cases
- Maintain good test coverage
- Use appropriate testing utilities

### Git Commit Messages

Use clear, descriptive commit messages:

```
feat: Add task filtering by priority
fix: Resolve WebSocket reconnection issue
test: Add E2E tests for file upload
docs: Update API documentation
refactor: Improve task update logic
```

### Before Submission

- [ ] All tests pass
- [ ] Code is properly formatted
- [ ] No console errors or warnings
- [ ] Documentation is updated
- [ ] README reflects all changes
- [ ] Application runs without errors

### Evaluation Criteria

Your submission will be evaluated on:

1. **WebSocket Implementation (10%)**
   - Real-time updates work correctly
   - Error handling is implemented
   - Connection state is managed

2. **React Component Structure (10%)**
   - Components are well-organized
   - Proper use of hooks
   - Code is reusable

3. **Testing (50%)**
   - Unit tests cover core functionality
   - Integration tests verify component behavior
   - E2E tests validate user workflows
   - Tests are well-written and meaningful

4. **Code Quality (20%)**
   - Clean, readable code
   - Good documentation
   - Proper error handling
   - Following best practices

5. **UI/UX (10%)**
   - Intuitive interface
   - Responsive design
   - Good user feedback
   - Accessible

### Questions?

If you have questions about the assessment:
1. Review all documentation files
2. Check the troubleshooting section
3. Examine the existing code for examples
4. Review the test files for usage patterns
